## 6b. ⚠️ H27 is a live bug with an 8x effect — and fixing it re-baselines everything

Verified against current code (F140), not just re-read:

- `src/backtest/runner.py:107` calls `generate_trades(...)` **without**
  `use_regime_filter`, so it takes the signature default **`True`**.
- `src/optimization/walk_forward.py:73` passes `use_regime_filter=_cfg.USE_REGIME_FILTER`
  → **`False`**.

So the **primary backtest and the primary OOS selector apply different entry gates.**
Quantified on synthetic OHLCV (no market data needed): the runner path yields **112
entries where walk-forward yields 898** — the backtest keeps **12.5%** of the OOS
selector's entries. Backtest and walk-forward numbers are therefore not comparable,
which is a concrete instance of the disconnect F2/F28/F30 describe.

**The fix is one keyword argument.** I did not apply it, because doing so changes
every backtest number in the project — that re-baselining is your call, not mine.
When you do:

1. add `use_regime_filter=config.USE_REGIME_FILTER` to the `runner.py` call;
2. `tests/test_web_code_claims.py::test_runner_still_omits_the_flag` will fail **by
   design**, with a message telling you to supersede H27 rather than edit the test;
3. supersede H27 (`note.py supersede H27 --by <new> --reason data-fixed`);
4. re-baseline any finding that quotes a backtest number.

F26 (slope gate dead-wired) is also confirmed and guarded the same way.
